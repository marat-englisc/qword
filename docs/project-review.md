# Аудит qword — 9 октября 2026

## Оценка

Основа проекта подходит его масштабу: Expo Router, локальная SQLite, отдельный прогресс
по каждому значению слова и FSRS. Полная смена архитектуры не нужна. Основные проблемы
были в конкурентном сохранении данных, восстановлении после ошибок и лишних обновлениях.
Они исправлены, а критичные сценарии закреплены регрессионными тестами.

## Исправленные проблемы

| Проблема | Исправление |
| --- | --- |
| База допускала несколько записей прогресса одного значения и повторное добавление колоды | Уникальные индексы; миграция объединяет дубликаты, сохраняет последнее состояние и весь журнал |
| Запросы разных экранов могли попасть в незавершённую транзакцию | Общая очередь с изоляцией всей транзакции и поддержкой вложенных savepoint |
| Параллельные ответы могли потерять прогресс или превысить дневной лимит | Проверка исходного состояния FSRS и дневного лимита внутри транзакции записи |
| Поздняя загрузка предыдущей сессии перезаписывала открытую | Версии запросов; новая сессия ждёт сохранения предыдущего ответа |
| После сохранения ответа и сбоя следующей загрузки интерфейс мог предложить ответить повторно | Сохранённая карточка сразу убирается; ошибка записи оставляет возможность повторить сохранение |
| Устаревшая карточка могла навсегда застрять после отклонённого ответа | Отдельная ошибка недоступной карточки и восстановление очереди без увеличения счётчика ответов |
| Обновление контента сохраняло удалённые примеры | Полная замена примеров и атрибутов обновлённых значений в одной транзакции |
| Сводка колод загружала все значения и считала их в JavaScript | Один SQL-запрос с агрегатами и корректным учётом пустых колод |
| Скрытые экраны продолжали опрашивать базу | Подписки работают только при фокусе и активном приложении; опросы последовательные |
| Практика пересчитывала FSRS каждую секунду | Предпросмотр фиксируется при раскрытии; очередь обновляется при наступлении срока |
| Большой каталог создавал все карточки сразу | Виртуализированный FlatList |
| Подписи прогресса уезжали за пределы карточек в браузере | Ограничена высота внешнего контейнера ProgressBar |
| Ошибки старта SQLite не имели рабочего повторного запуска | Экран загрузки и обработчик ошибки с повторным открытием провайдера |
| Озвучка могла продолжиться после ухода со страницы | Остановка при уходе и переходе в фон; защита от поздних callback |
| Адреса колод, ошибки примеров, контраст текста и уменьшение анимаций | Проверка ID, повтор загрузки, подписи доступности, исправленный контраст и системная настройка анимаций |

Удалён неиспользуемый шаблон App.tsx. TypeScript наследует настройки Metro из Expo.
dotenv и libSQL перенесены в зависимости разработки; добавлены явные типы Node.js
для инструментов и тестов. Локальные пользовательские изменения `local.db` сохранены.

## Проверки

- Lint и проверка типов.
- 36 регрессионных тестов: настоящая SQLite в памяти, очереди FSRS и гонки состояния.
- Проверка SDK-совместимости и Expo Doctor: 21 из 21 проверки.
- Экспорт web и компиляция Hermes для Android и iOS.
- Целостность исходной SQLite: integrity_check = ok, нарушений внешних ключей нет.
- Браузер: просмотр колоды и значения, добавление колоды, раскрытие ответа,
  сохранение оценки и ожидание следующего повторения; проверка ширины 390 пикселей,
  сохранности прогресса после нового запуска и повтор запуска после ошибки загрузки базы.

Экспорт JavaScript/Hermes подтверждает сборку кода. Установку приложения, системную
озвучку и поведение на физических Android/iOS-устройствах нужно проверять отдельно.

## Оставшиеся ограничения

Актуальный npm audit обнаруживает предупреждения high и moderate в сторонних
зависимостях, включая повторные предупреждения всей цепочки одного уязвимого пакета. Основные причины:
braces в инструментах сборки, node-forge в Expo CLI и decode-uri-component в Expo Router.
Для первых двух пакетов проверенные последние версии всё ещё отмечены уязвимыми.
decode-uri-component 0.5 исправляет проблему, но его ESM-экспорт несовместим с прямым
CommonJS-вызовом в установленном query-string 7. Принудительное автоисправление предлагает
несовместимые версии Expo/React Native/Tailwind. Оно не применено; нужен совместимый
релиз upstream либо отдельная проверенная миграция SDK. Отчёт: `npm audit`.

Web SQLite остаётся экспериментальной функцией Expo. Для размещения нужны COOP/COEP
заголовки; локальное превью настроено в проекте. Официальное описание:
[Expo SQLite SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/).

Контент текущей исходной базы очень небольшой: две колоды, одно слово, одно значение,
без примеров. Наполнение и редакторская проверка учебных материалов — отдельная работа.
Отсутствующие в обновлении слова и значения сохраняются на устройстве намеренно;
механизма архивирования контента пока нет. Дневной лимит использует время устройства.
Резервное копирование и синхронизация пользовательского прогресса в текущий продукт
не входят.
